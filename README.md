# 어디가? (WhereTo?)

지도에서 범위를 선택하고 그 안의 장소 후보를 무작위로 추천받는 앱입니다. GPS 권한 없이도 지역 검색이나 지도 이동으로 시작할 수 있습니다.

기존 공개 배포: [whereto-swart.vercel.app](https://whereto-swart.vercel.app). 로컬 변경이 자동으로 배포되는 것은 아닙니다.

## 기능

- 카카오 JavaScript 키 설정 시 지도·지역 검색·추첨 장소 조회를 함께 카카오로 전환
- 키 없이도 OpenFreeMap 지도와 Photon 검색으로 개발 미리보기 실행
- 전체 화면 지도, 모든 화면의 WhereTo 홈 링크, 작은 도구 버튼과 접을 수 있는 메뉴
- 지도에 점을 찍어 다각형 영역 지정, 마지막 점 취소·전체 지우기, 결과 화면에서 영역 재지정
- 상단 가로 스크롤에서 `전체`와 카카오 18개 카테고리를 단일 선택, 결과·선택 카테고리의 새로고침 유지
- 링크 복사·시스템 공유, 독립된 Liquid Glass 팝업에서 카카오맵·Google Maps·Apple Maps 길찾기 선택
- 브라우저 방문 기록 저장·수정·삭제 취소·지도 재열기
- JSON 내보내기·병합 가져오기, 저장소 오류 시 원본 백업과 복구 안내
- 키보드 범위 선택, 모달 포커스 관리, 모바일 주소 줄바꿈, 화면 확대 지원

## 실행과 검증

Node.js 24 이상을 사용합니다. 프론트엔드는 백엔드나 DB 없이 실행됩니다.

```powershell
cd frontend
npm ci
npm run dev -- --host 127.0.0.1 --port 5180 --strictPort
```

브라우저에서 `http://127.0.0.1:5180`에 접속합니다. `npm run dev`만 실행하면 Vite 기본 포트는 5173입니다.

```powershell
npm run lint
npm test
npm run build
```

테스트는 외부 API를 실제 호출하지 않고 입력 검증, 공급자 응답 처리, 추첨 후보, 요청 제한·타임아웃·취소·캐시, 공유 문자열 및 저장 데이터 복구를 검증합니다. GitHub Actions가 프론트와 백엔드의 테스트·빌드·타입 검사 및 개발 의존성을 포함한 `npm audit --audit-level=low`를 수행합니다. 자동 테스트 통과와 실제 카카오 계정·도메인에서의 연결 확인은 별도입니다.

실제 카카오 앱에서 키·API 활성화·허용 도메인을 설정한 뒤 지도 표시·키워드/주소 검색·식당 추첨을 직접 확인합니다. 테스트의 대역 응답은 카카오 계정 설정 확인을 대신하지 않습니다.

선택적 백엔드의 실행·인증·마이그레이션 절차는 [backend/README.md](backend/README.md)에 있습니다. Express 앱은 Vercel에 직접 내보내고 로컬에서는 별도의 `server.ts`를 실행합니다.

## 카카오 연결

1. [Kakao Developers](https://developers.kakao.com/)에서 앱을 생성하거나 사용할 앱을 선택합니다.
2. 앱 관리의 **카카오맵 → 사용 설정**에서 API를 활성화합니다.
3. **앱 → 플랫폼 키 → JavaScript 키**에서 키를 확인합니다. 지도 Web SDK에는 JavaScript 키를 사용하며 REST API 키나 Admin 키를 넣지 않습니다.
4. JavaScript 키의 **JavaScript SDK 도메인**에 실제 접속 주소를 등록합니다.

   | 용도 | 등록할 주소 |
   | --- | --- |
   | 로컬 개발 | `http://localhost:5180`, `http://127.0.0.1:5180` |
   | Vite 기본 포트를 사용할 때 | `http://localhost:5173`, `http://127.0.0.1:5173` |
   | 현재 공개 사이트 | `https://whereto-swart.vercel.app` |
   | 별도 배포·미리보기·커스텀 도메인 | 실제 사용하는 각 사이트의 도메인 |

5. 처음 설정할 때 `frontend/.env.example`을 `frontend/.env.local`로 복사하고 아래 값을 채웁니다. 이미 `.env.local`이 있다면 덮어쓰지 말고 해당 항목만 수정합니다.

   ```dotenv
   VITE_KAKAO_MAP_APP_KEY=발급받은_JavaScript_키
   ```

6. 개발 서버를 다시 시작합니다. Vercel에서는 프론트 프로젝트의 환경변수에 같은 이름으로 설정하고 다시 배포해야 합니다. Vite 환경변수는 빌드에 반영되므로 기존 배포 화면에 즉시 적용되지 않습니다.

`.env.local`은 Git에서 제외됩니다. JavaScript 키는 브라우저 SDK에서 사용하므로 번들과 요청에 노출됩니다. 허용 도메인으로 사용처를 제한하고 비밀 REST/Admin 키를 프론트 환경변수에 넣지 않습니다. 설정 위치와 도메인 규칙은 [공식 앱 설정](https://developers.kakao.com/docs/ko/app-setting/app), SDK 사용 방식은 [공식 지도 가이드](https://apis.map.kakao.com/web/guide/)를 참고합니다.

SDK가 HTTP 403과 `disabled OPEN_MAP_AND_LOCAL service`를 반환하면 해당 앱의 **카카오맵 → 사용 설정**이 비활성화된 상태입니다. 키를 다시 발급하기 전에 API 활성화 여부를 확인합니다. 도메인 인증 오류가 발생하면 현재 브라우저의 프로토콜·호스트·포트가 JavaScript SDK 도메인 등록과 일치하는지 확인합니다.

2026-10-08 확인 기준, 새로 활성화하는 앱은 개발자 계정에서 최초 카카오맵 활성화 앱에 무료 쿼터가 제공됩니다. 두 번째 이후의 신규 활성화 앱이나 무료량 초과 이용은 비즈월렛·유료 API 설정이 필요합니다. 2026-07-21 이전부터 이용하던 앱의 기존 무료 쿼터는 유지된다는 예외가 있습니다. 앱의 무료 쿼터 배지와 실제 사용량을 확인하세요. [카카오맵 이용 조건](https://developers.kakao.com/docs/ko/kakaomap/common), [변경 공지](https://devtalk.kakao.com/t/api-notice-on-new-kakao-map-api-features-and-free-quota-policy/150222)

## 지도와 장소 조회

`VITE_KAKAO_MAP_APP_KEY`가 있으면 카카오 지도 Web SDK와 `services`를 함께 로드하여 지도 표시·지역 검색·추첨 후보를 모두 카카오로 처리합니다. 키가 있는데 로딩·인증·네트워크 요청이 실패하면 오류와 재시도를 표시합니다. 다른 공급자로 조용히 전환하지 않습니다.

카카오 모드의 동작은 다음과 같습니다.

- 지역명·장소명은 키워드 검색을 먼저 사용하고, 결과가 없으면 주소 검색을 시도합니다.
- 상단 바는 `전체, 음식점, 카페, 편의점, 대형마트, 문화시설, 관광명소, 숙박, 주차장, 주유소·충전소, 지하철역, 은행, 병원, 약국, 공공기관, 중개업소, 학교, 학원, 어린이집·유치원` 순서입니다. 클릭·터치로 선택하고 좌우 스크롤로 이동합니다. 결과 화면에서 카테고리를 바꾸면 기존 결과를 지우고 대기합니다. `뽑기`를 눌러 같은 범위 안의 새 카테고리 장소를 추첨합니다.
- `전체`는 카카오 18개 분류 가운데 조회당 4분류를 무작위로 선택해 API가 제공한 후보를 사용합니다. 지역의 모든 장소를 수집하거나 모든 장소에 같은 추첨 확률을 보장하지 않습니다.
- 개별 카테고리는 해당 카카오 분류의 장소만 사용합니다. 예를 들어 `음식점`은 `FD6`, `카페`는 `CE7`이며 서로 대체하지 않습니다. 기존 `category=restaurant` 링크도 유지됩니다.
- 지도에 점을 3개 이상 찍고 `지정`을 누르면 마지막 점과 첫 점을 연결한 다각형 영역을 확정합니다. 이어서 `뽑기` 버튼을 눌러 해당 영역 안의 장소를 추첨합니다. 오목한 다각형도 지원하며, 선이 교차하거나 면적이 없는 영역은 지정할 수 없습니다. 점은 최대 50개이고 마지막 점 취소·전체 지우기를 지원합니다. 드래그는 지도 이동에 사용합니다.
- 다각형 내부에서 조회 좌표를 뽑고, 주변 5km의 후보 중 실제 장소 좌표가 선택한 다각형 안에 있는지 다시 검사합니다. 한 번의 추첨은 최대 3회 주변 조회를 시도하며, 조건에 맞는 후보가 없으면 영역 재지정을 안내합니다. 기존 사각형 결과 링크도 계속 열 수 있습니다.
- 결과 화면의 `영역 재지정`은 현재 영역과 카테고리를 가져와 편집합니다. `지정` 후에는 새 영역의 추첨 대기 상태가 되며 `뽑기`를 눌러 추첨합니다. 취소하면 기존 결과로 돌아갑니다. 새 추첨은 `뽑기` 또는 `다시 뽑기` 버튼에서만 시작하며, 재추첨·카테고리 변경·새로고침에서도 지정한 다각형을 유지합니다.
- 공급자의 검색·분류 결과를 사용하므로 실제 출입 가능 여부·영업 여부·보행 경로를 보장하지 않습니다. 공개 SDK에 요청 취소 기능이 없으므로 화면 이탈 시에는 늦은 결과 반영을 막습니다.

키가 없으면 기존 개발 미리보기 구성을 사용합니다.

- 지도는 [OpenFreeMap Bright](https://openfreemap.org/quick_start/)를 MapLibre로 렌더링하며, 한국어 이름이 있으면 우선 표시합니다. WebGL2를 사용할 수 없을 때에는 [OpenStreetMap 표준 타일](https://operations.osmfoundation.org/policies/tiles/)을 사용합니다. 출처를 표시하고 타일 대량 수집·오프라인 다운로드는 제공하지 않습니다.
- 검색과 추첨 후보는 [Photon](https://github.com/komoot/photon)을 사용합니다. 개별 카테고리는 대응하는 OSM 태그로 검색하고 후보를 다시 검사합니다. 예를 들어 음식점은 일반 식당·패스트푸드·푸드코트이며 카페는 제외합니다. 지역의 태그 등록 상태에 따라 결과가 적을 수 있습니다. 주소에 '강'이 포함되는지 같은 문자열 추측으로 수역을 판단하지 않습니다.
- Photon 요청은 브라우저 내에서 직렬화하며 최소 1.1초 간격, 10초 타임아웃, 5분 캐시를 적용합니다. 공개 서버는 적정한 사용량을 전제로 하며 가용성을 보장하지 않습니다. 대규모 운영에는 계약된 공급자나 자체 서버와 공유 요청 제한이 필요합니다.

`VITE_GEOCODER_URL`, `VITE_MAP_STYLE_URL`, `VITE_MAP_TILE_URL`, `VITE_MAP_ATTRIBUTION`은 키가 없는 미리보기 공급자 설정입니다. `VITE_MAP_TILE_URL`을 지정하면 벡터 지도 대신 래스터 지도를 사용합니다. 세부 예시는 [frontend/.env.example](frontend/.env.example)에 있습니다. 공개 Nominatim 엔드포인트는 호출하지 않습니다.

## 저장과 공유

방문 기록은 현재 기기·브라우저의 `localStorage`에만 보관됩니다. 서버 동기화와 계정 기능은 없습니다. 지도 공급자를 바꾸어도 저장 방식과 기존 기록은 유지됩니다. 기존 배열 형식도 읽으며 이후 저장 시 버전 1 형식으로 기록합니다. 손상되거나 알 수 없는 버전은 조용히 덮지 않습니다. 원본을 내려받은 뒤 사용자가 명시적으로 초기화할 수 있습니다.

가져오기는 기존 기록을 유지하면서 병합하고, 동일 내용은 건너뜁니다. 같은 ID의 다른 기록은 새로운 ID로 보존합니다. 삭제 취소는 해당 갤러리 화면을 떠나기 전까지 가능합니다.

저장·내보내기·가져오기는 같은 JSON 형식과 UTF-8 20MB 상한을 사용합니다. 브라우저 자체의 저장 공간 한도는 이보다 작을 수 있으며, 저장에 실패하면 기존 기록을 유지합니다. 다른 탭이 수정한 기록을 오래된 편집 화면으로 덮어쓰려 하면 충돌을 알리고 입력 내용을 유지합니다. Web Locks를 지원하는 브라우저에서는 저장 작업을 탭 사이에서도 직렬화합니다. 미지원 브라우저에서는 오래된 편집 검사는 유지되지만 정확히 동시에 실행된 탭 간 저장까지 직렬화하지는 못합니다.

## 보안 설정

`frontend/vercel.json`은 CSP로 외부 스크립트·통신 출처를 제한하고 인라인 스크립트·eval·프레임 삽입·플러그인·외부 폼 제출을 차단합니다. `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`도 설정합니다. 카카오 지도와 유리 효과가 사용하는 동적 스타일 때문에 CSS 인라인 스타일은 허용하며, 스크립트 인라인 실행은 허용하지 않습니다. 카메라·마이크·결제·USB 접근은 차단하고 위치는 현재 사이트에서 사용자가 허용한 경우에만 사용할 수 있습니다. [CSP 지침](https://developer.mozilla.org/en-US/docs/Web/Security/Practical_implementation_guides/CSP)

`npm run preview`도 같은 헤더를 적용하므로 배포 전 운영 빌드로 지도·검색·추첨을 확인할 수 있습니다. Vite 개발 서버의 HMR에는 이 운영용 CSP를 적용하지 않습니다. 지도·검색 공급자를 환경변수로 바꾸면 해당 출처를 CSP의 `img-src`/`connect-src` 등에 함께 등록해야 합니다. 카카오 JavaScript 키는 공개 브라우저 키이며, 사용 도메인 제한은 카카오 콘솔에서 관리합니다.

공유 URL에는 좌표·주소가 포함되며 링크를 가진 사람은 내용을 볼 수 있습니다. 별도 서버 저장 없이 생성하므로 만료나 회수 기능은 없습니다. 서버의 선택적 토큰 공유 API와는 별도입니다. DB API는 기본 비활성 상태이며 운영자 토큰 없이는 방문 기록을 읽거나 수정할 수 없습니다. 사용자별 서버 저장소로 연결하려면 사용자 인증·소유권 모델을 먼저 구현해야 합니다.

## 기술

오른쪽 위 설정에서 기본 Liquid Glass와 기존 클래식을 전환하고, 유리 틴트 농도를 0~100%(기본 80%)로 조절합니다. 이미 저장한 농도는 유지하며 초기화 버튼은 80%로 되돌립니다. 설정은 브라우저에 저장하며 결과·다각형 편집 상태를 유지합니다. Chromium에서는 실제 지도 배경의 SVG 굴절·미세한 RGB 색분산을 적용하고, 다른 엔진은 blur/반사광으로 표시합니다. 호버·누름·드래그의 반사광과 압축·스프링 복원, 이동 속도에 따라 늘어나는 카테고리 렌즈를 적용했습니다. 모션은 기본으로 켜지며 설정에서 직접 끌 수 있고, Liquid Glass는 시스템 동작 줄이기와 별개로 앱 내 선택을 사용합니다. 시스템 투명도 감소·고대비 설정 및 클래식의 동작 줄이기는 유지합니다. Apple 시스템 렌더러 자체가 아닌 웹 구현이며 [세부 구조와 제한](frontend/README.md#디자인-전환과-liquid-glass)을 참고합니다.

React 19 · TypeScript(strict) · Vite 8 · Tailwind CSS 4 · Kakao 지도 Web SDK.
키 없는 미리보기: Leaflet · MapLibre GL · Photon.
선택적 서버: Express · Prisma · PostgreSQL.
